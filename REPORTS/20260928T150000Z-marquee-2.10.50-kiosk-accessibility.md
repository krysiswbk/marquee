## FINDINGS

The discrepancy was confirmed in source and rendered behavior. `kiosk-menu.js`
created the selected destination as a sibling overlay but left the dashboard
siblings in the accessibility tree and potentially focusable. The fix gives the
overlay an explicit lifecycle: the pre-existing dashboard siblings are stored,
set `inert` and `aria-hidden="true"` for active destinations, and restored from
their original values on Home or interruption. Destination navigation uses
history entries so browser back returns to Home; Escape and Home restore the
Home rail link focus.

Follow-up inspection found that a brand-new direct destination load still left
focus on the document body. The release now keeps an initial-direct-focus
pending flag and focuses the visible selected-region heading after its first
non-loading render. It preserves that heading through host refresh rerenders,
restores Home focus after deferred browser-history focus restoration, and moves
focus to the current rail target before hiding an active Now Playing surface.
It does not run for passive Home loads or clicked rail navigation. The browser
regression asserts direct-load heading focus and safe empty/active Now Playing
transitions.
