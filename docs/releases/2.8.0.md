# Marquee 2.8.0 — household attention

The new attention service sits between source observations and presentation. It
normalizes provider and HA signals, enriches them with semantic house context,
evaluates declarative escalation/modifiers, and arbitrates per display with
explanations. Lifecycle, grouping, acknowledgement, cooldown, debounce, source
freshness and critical preemption are covered by deterministic tests.

The existing ContextArbiter remains the ambient strategy, preserving manual
navigation/freeze, pleasant rotation, UFC-over-PFL precedence, Cast eligibility
and raw radar rendering. Native weather alerts now have an IMPORTANT attention
policy. Household example rules are unbound until real HA entities are configured.

Use `/admin/attention` to inspect signals, stages, score components, suppressed
items, display winners and bounded history, acknowledge items or edit policy JSON.
The optional AppDaemon producer uses server-provided bindings; existing HA
 automations need no changes. Garage Cast delivery has a separate display ID.

Validation: 183 pytest tests plus 14 subtests; scoped Ruff and strict mypy across
17 new modules; application selftest; real-app Playwright ingestion, rendering,
acknowledgement and resolution smoke test; 1280px and 390px manual-control/radar
browser regression checks.

Reproduce the local browser smoke check with optional Playwright installed:

```
MARQUEE_CHROMIUM=/path/to/chromium python tests/smoke_attention.py
```

This starts a temporary local app on port 18084 with providers and Cast devices
unconfigured, exercises test signals, and terminates it. It never sends synthetic
household conditions to production.

Remaining architecture debt is explicit: ambient integrations still use their
established compatibility strategy; additional physical Cast transports require
runtime wiring; display availability comes from configuration/adapters; audio/video
alert renderers are future extensions; Cast launch latency still includes the
existing media/reconciliation loop. Household entity bindings and the optional HA
producer must be configured before door/leak/appliance examples can become live.
